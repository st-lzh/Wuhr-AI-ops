# 运维控制平面使用手册

本文说明 Wuhr AI Ops 新增的作业、事件、集群、知识、告警、制品和凭据治理模块。所有业务记录均写入 PostgreSQL；前端 Docker 容器重建不会删除数据，前提是保留 `postgres_data` volume。

## 1. 作业中心

“作业中心 → 作业管理”用于把已经确认的运维命令固化成确定性作业。

1. 填写作业名称、命令和目标主机。
2. 可填写 Cron 表达式；调度时区固定为 `Asia/Shanghai`。
3. 系统会识别命令风险。高风险和严重风险命令强制每次审批，不能通过页面关闭。
4. 单次运行只保存一份命令快照，然后由程序并发发送到目标主机，不会为每台主机重复调用模型。
5. 在“执行记录”查看每台主机的退出码、标准输出、标准错误和耗时。

定时作业和计划部署由独立 `deployment-scheduler` 容器调度。审批、执行结果和失败事件都可追溯。

## 2. 事件中心

事件中心汇聚自动化失败和外部告警。事件可以确认、进入调查、分派、解决或重新打开；状态与处理人都会持久化。

外部监控接入步骤：

1. 进入“接入管理 → 告警接入”。
2. 新建 Alertmanager 或通用 Webhook 来源。
3. 立即保存页面仅显示一次的 Bearer Token。
4. 把 Webhook URL 和 Token 配置到外部监控系统。
5. 发送告警后，在事件中心检查指纹聚合、出现次数、严重级别和恢复状态。

平台数据库只保存接入密钥的 SHA-256 哈希。轮换密钥后旧密钥立即失效。

## 3. 集群管理

集群管理不把 kubeconfig 上传到浏览器或数据库。每个集群记录映射到一台已登记的 Agent 主机，以及该主机上的 kubeconfig context。

1. 先在主机管理添加能够执行 `kubectl` 的 Agent 主机。
2. 在集群管理填写 context 和默认 namespace。
3. 点击“测试”，平台会通过 SSH 在 Agent 主机上真实执行 `kubectl version` 和 namespace 查询。
4. 测试通过后，可在智能助手输入框使用 `@集群名`，系统会自动切换 K8s 模式并限定 context 与 namespace。

## 4. 知识管理

知识管理用于团队共享运行手册、故障案例和规范。

1. 可手工录入或读取 `.txt`、`.md`、`.log`、`.json`、`.yaml` 等文本文件。
2. 单篇最多 500KB，保存后写入 PostgreSQL，并按自然段分块。
3. 当前检索明确标记为“关键词检索”，没有配置向量模型时不会伪装成语义检索。
4. 智能助手输入区可引用最多三篇知识文档。模型收到文档正文和来源名称，并被要求区分历史资料与实时检查结果。

输入区的临时文件只用于当前会话；需要长期保存的内容应进入知识管理。

## 5. 制品管理

“接入管理 → 制品管理”用于登记 Harbor 或 Docker Registry。

1. 填写仓库 URL、项目/命名空间和机器人账号或访问令牌。
2. 密码使用 AES-256-GCM 加密，列表接口不会返回明文。
3. 点击“测试”会真实访问 Registry V2 `/v2/` 接口并保存状态、耗时和错误。
4. 内网自签名仓库可以显式关闭 TLS 校验，但平台会持续显示风险标记。

## 6. 凭据治理

“安全治理 → 凭据治理”只展示脱敏清单，不解密或返回任何凭据。它聚合主机、网络设备、Git、Jenkins、Grafana、ELK、模型和制品仓库的真实记录。

- “当前加密”表示数据使用 AES-256-GCM 新格式保存。
- “历史格式”表示兼容旧密文或历史明文，应前往对应管理页重新保存。
- “超 180 天”表示记录长时间未更新，需要人工确认是否轮换，不代表凭据一定失效。

所有新增、修改、测试、审批和执行动作都会写入“安全治理 → 审计日志”。

## 7. 数据与容器

正常的镜像重建或容器重启不会丢失数据：

```bash
docker compose up -d --build
docker compose restart app deployment-scheduler
```

不要执行 `docker compose down -v`，因为 `-v` 会删除 PostgreSQL 和 Redis volume。
